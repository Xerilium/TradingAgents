# UI Missed Opportunities: Capabilities Built in Nautilus & Backend Components Not Fully Surfaced in the UI

- **Date:** 2026-10-28
- **Scope:** Audit of all 143 Python backend modules (`tradingagents/web/`, `tradingagents/dataflows/`, `tradingagents/integrations/`, `tradingagents/memory/`, `tradingagents/agents/`) against what `tradingagents/web/static/app.js`, `nautilus.js`, `command-controls.js`, `report-format.js`, and `workflows.js` actually expose to the trader.

---

## Executive Summary

**Yes — there are 24 concrete capabilities already built into our Python backend, NautilusTrader 1.231.0 worker, Laya, Maenifold, and data vendors that the current UI either never exposes, buries inside `<pre>` JSON dumps, or hides behind 4 levels of clicks.**

See also the companion deep-dive on the Nautilus runtime and execution layer in [`docs/ui-missed-opportunities-nautilus.md`](ui-missed-opportunities-nautilus.md).

We grouped all 24 missed opportunities into:
- **Category A (19 items) — Zero-Backend-Work Missed Opportunities:** Already returned in `/api/state` or existing `/api/*` endpoints, or accepted as request parameters today, but missing or buried in the UI.
- **Category B (5 items) — One-Step Read-Only Pass-Throughs:** Already implemented in `tradingagents/` Python modules (`service.py` clock pass-through, `report_html.py`, `reflection.py`, `settlement.py`, `polymarket.py`/`fred.py`, `laya_review.py`), needing only a small read-only surface in the UI.
